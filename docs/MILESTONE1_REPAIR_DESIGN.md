### 3.2 Diff tool (ready for when the snapshot arrives)
`scripts/diff_executor_sources.py --snapshot <path> --current research/paper_described_baseline.py --out docs/executor_diff/`:

1. Hash the snapshot; if it does not equal `619ad2f4...726f`, print MISMATCH, write `snapshot_hash_mismatch.json`, exit 2, and produce NO classification (never substitute).
2. If it matches, write a unified diff (`difflib`, LF-normalized only for display; hashes always computed on raw bytes) to `docs/executor_diff/executor_vs_current.diff`.
3. Classify each hunk by the enclosing top-level function using `ast`: region map `prepare_data`, `audit_splits` -> data_prep; `run_seed` training loop, optimizer, `state_hash` -> training; `fgsm_attack`, `pgd_attack` -> attack_generation; `evaluate_seed`, `compute_logits` -> evaluation; `verify_seed`, `main`, report/log/atomic writers, docstrings and comments -> verification_reporting_only. A hunk touching an unmapped region is classified `unclassified`. Output `classification.json` with counts per class and the verdict "affects results: yes/no/unknown" (unknown if any `unclassified`). Comment- or docstring-only hunks are detected via `ast.dump` equality of function bodies without docstrings.
4. Never writes into any `runs/` directory. Teammate files live under `external_evidence/teammate-mac/` (new directory, git-ignored through a new `.gitignore` entry; see 6) and are never copied over `runs/`.

`scripts/verify_teammate_evidence.py` hashes everything copied there against the expected values embedded from the inventory JSON (checkpoints, manifests, config, environment, executor), writes `external_evidence/teammate-mac/verification.json`, reports a missing/mismatched list, and fabricates nothing.

### 3.3 Upstream snapshot and dependency environment
- Upstream: `provenance.upstream_tree_hash(dir)` = SHA-256 over sorted `relpath + NUL + sha256(bytes)` lines for every file under `upstream/PAVE_artifact/code` excluding `__pycache__`, plus `LICENSE`. For C this is computed from the pinned upstream (HEAD must equal `e73911bb...fd4`, `git status --porcelain --untracked-files=all` empty, dataset SHA equals `0d869e33...53ed`), then the code is copied to `runs/.../reference/code` and the copy is re-hashed and must equal the source hash. ### 3.4 Resume compatibility (corrected runs only)
`provenance.compute_fingerprint(cfg, root)` (read-only and in-memory, see the order of operations below [S3]) returns a dict of five component hashes plus a combined hash:

| Component | Content |
| --- | --- |
| `config` | SHA-256 of canonical JSON (`sort_keys`, `separators=(",",":")`, UTF-8) of the config. ALL keys are included, including `_`-prefixed documentation keys, so documentation edits also invalidate resume (stricter, simpler) |
| `executed_source` | SHA-256 of sorted `(relpath, sha256)` pairs of exactly four files read as raw bytes: `research/paper_described_adam.py`, `research/adversarial_domain.py`, `research/provenance.py`, `research/milestone1.py`. The per-file hashes are stored in `fingerprint.json["components"]["executed_source"]["files"]` (a map relpath -> sha256) next to the combined hash, so each is independently verifiable [R4][R10] |
| `upstream_source` | upstream tree hash from 3.3 |
| `data` | dataset SHA, `split_ids.json` SHA (the shared saved split, read from `cfg["split"]["source"]` and hash-verified), preprocessing array hashes (scaler min/scale, fit in memory on the saved training rows; nothing is written) |
| `environment` | the strict subset: python major.minor.micro, torch, numpy, pandas, sklearn versions, `platform.system()`, `platform.machine()`; hardware strings are recorded but are not part of the fingerprint |

On first start the runner writes, at RUN level (not per seed; this is the single location, and the evidence copy is `evidence/executor_snapshot.py` at evidence root, which the checker reads) [Q6], `fingerprint.json` and `executor_snapshot.py` (a copy of `paper_described_adam.py`) and also `executed_sources/` (byte copies of the other three hashed files, preserving file names), each via `atomic_*` helpers, then verifies by re-reading that every copy's hash equals its entry in `fingerprint.json`. The checker (9.3) recomputes each per-file hash from the evidence copies and recomputes the combined hash from them. [R4] The snapshot is therefore a true copy of what was imported by that process; the hash is computed from the same bytes that are copied (read once into memory, hash and write that buffer) so a race with editing is impossible.

Gate scope (revised): the run-level `fingerprint.json` is the single source of truth for the whole run directory. On EVERY launch that targets a run directory in which `fingerprint.json` already exists, whether it is a `--resume` of a partial seed or a fresh start of a new seed (for example seed 7 after seed 1), `provenance.check_resume(root, current_fingerprint)` runs first. A source edit between seeds therefore blocks the later seeds until the user restores the sources or starts a new run directory. The first launch into an empty or absent run directory creates `fingerprint.json`. A launch into a run directory that has content but no `fingerprint.json` is refused. [R3]

Order of operations in `main` [S3]. The order is fixed and is part of the contract:

1. Parse arguments and read the config with `read_adam_config` (reads only; verifies the split file hash).
2. `provenance.compute_fingerprint(cfg, root)` is READ-ONLY and in-memory. It writes nothing anywhere (no run directory, no temp file in the repository, no cache). Its inputs are: the config bytes; the four executed-source files and the upstream tree, read from their repository paths; the dataset CSV (hash only); the saved split read from `cfg["split"]["source"]` (`reports/milestone1-paper-described/split_ids.json`), whose SHA-256 is verified against `cfg["split"]["sha256"]` BEFORE it is used (the run-directory copy of `split_ids.json` is never consulted at gate time, and may not exist yet); the training rows selected by those saved IDs, from which the `MinMaxScaler` is fit in memory to obtain the min/scale array hashes of the `data` component; and the environment subset. The scaler fit is discarded after hashing; `prepare_data_adam` fits its own scaler later and the runner asserts its array hashes equal the ones in the fingerprint.
3. `provenance.check_resume(run_dir, current_fingerprint)` runs next, FIRST among all operations that can write: before the lock file is created, before `status.json`, before any log is opened, before `executor_snapshot.py`, `executed_sources/`, `split_ids.json`, `split_overlap_audit.json`, `fingerprint.json` or any existing file is touched or any directory is created. It reads the run-level `fingerprint.json` (if present), compares each component, and on any difference raises `ResumeIncompatibleError` listing the differing components with both hashes.
4. Only after `check_resume` returns normally do the writing steps run, in this order: lock file, `status.json`, log opening, `fingerprint.json` and snapshot copies (first launch only), then `prepare_data_adam` (the Adam data preparation, which copies `split_ids.json` into the run directory and writes `split_overlap_audit.json`, `preprocessing.*`, `data_range_report.json`), then training.

Exit code 3 is returned for EVERY refusal at the gate, with the message printed to stderr and nothing written [S3]: (a) a fingerprint component MISMATCH, (b) a run directory that has any content (any file or subdirectory) but no `fingerprint.json`, (c) an `epoch-NN.pt` whose stored `fingerprint_sha256` differs from the current one (checked before the loaded checkpoint is used for anything), and (d) a `fingerprint.json` that exists but cannot be parsed or lacks a component. The gate also covers launches by `--verify-only` and `--smoke`. A run directory that is absent or empty is not a refusal; the first launch creates `fingerprint.json` after the gate passes. There is no "adopt" path. A fresh start still refuses a non-empty existing seed directory unless `--resume` is given (same behavior as B), also with exit code 3 and no writes.

Smoke directory [S6]: the smoke (5.2) writes its own run-level `fingerprint.json` into `runs/milestone1-paper-described-adam-smoke/` using the SAME `compute_fingerprint` function, and is subject to the same gate: `main --smoke` runs steps 1 to 4 above against the smoke directory, so a smoke re-launch after any config, source, upstream, data or environment change is refused with exit code 3 unless the smoke directory is absent or empty (the user starts a new smoke directory; smoke output is never overwritten). The smoke fingerprint is not interchangeable with the full-run fingerprint: the full runner never reads it and refuses `--run-dir` equal to or inside the smoke directory.

Zero-write test (see Group C test 8 in 12.1): a REJECTED launch is executed with `builtins.open` (any mode containing `w`, `a`, `x` or `+`), `os.replace`, `os.rename`, `os.makedirs`, `os.mkdir`, `shutil.copyfile`/`shutil.copy2`, `Path.write_bytes`/`Path.write_text` and `tempfile.mkstemp` patched with spies that record the call and raise `AssertionError`; the test asserts exit code 3 and an empty spy log, in addition to the byte-for-byte tree hash comparison of test 2.

Additionally every epoch checkpoint stores `fingerprint_sha256`; before loading `epoch-NN.pt`, its fingerprint must equal the current one, else the same error (still before modification).

A single-writer lock like B's `run.lock` is kept (PID plus create time) because it's an existing, working pattern.

Failure behavior summary:

| Failure | Recoverable | Caller receives | Log |
| --- | --- | --- | --- |
| Fingerprint mismatch on resume or fresh seed [S3] | No (user must restore sources or start a new run dir) | exit code 3, message listing components | stderr; ERROR-level line in `raw.log` is NOT written because the log is not opened |
| Run directory has content but no `fingerprint.json` (or unreadable `fingerprint.json`, or checkpoint fingerprint differs) [S3] | No (start a new run dir) | exit code 3, message naming the cause | stderr only; nothing written |
| Upstream HEAD/dirty/dataset mismatch | Fatal | exit 4, `ValueError` | stderr |
| Snapshot self-verification mismatch | Fatal | exit 4 | stderr |
| Run already active (lock) | Recoverable by waiting | exit 5 | stderr |

## 8. Item 6: adversarial domain handling (`research/adversarial_domain.py`)

Pure functions, no I/O, torch-only.

```
class InfeasibleConstraintError(ValueError)   # carries count, first indices, max violation, eps
def feasible_bounds(x: Tensor, eps: float) -> tuple[Tensor, Tensor]
def project(x_adv: Tensor, lower: Tensor, upper: Tensor) -> Tensor
def fgsm(model, x: np.ndarray, y: np.ndarray, eps: float, batch_size: int) -> np.ndarray
def pgd(model, x: np.ndarray, y: np.ndarray, eps: float, alpha: float, steps: int,
        base_seed: int, batch_size: int, return_trajectory: bool = False)
        -> np.ndarray | tuple[np.ndarray, list[np.ndarray]]   # trajectory = init + every iterate; test-only, default False [R8]
def assert_clean_inputs_finite(x) -> None
```

Behavior:

- Validation of inputs: `eps` finite and `>= 0` (else `ValueError`, fatal); `alpha > 0` and `steps >= 1` for PGD; `x` float32 ndarray of shape `(n, 50, 39)` with all values finite (else `ValueError` naming the first bad index); `len(x)==len(y)`; labels int in `[0,26]`. No input is mutated.
- eps = 0: return `np.array(x, copy=True)` immediately, before any model call, with no projection and no feasibility check. Documented: for eps = 0 no perturbation or domain correction is performed even for out-of-range clean inputs.
- eps > 0: `lower = torch.clamp(x - eps, min=0)`, `upper = torch.clamp(x + eps, max=1)` (i.e. maximum(x-eps,0) and minimum(x+eps,1)), computed in float32 once from the ORIGINAL x. If `(lower > upper).any()` raise `InfeasibleConstraintError` with the count, up to 10 flat indices (row, step, feature) and the maximum of `lower-upper`. No widening, no clamp of x, no dropping. The error is fatal for that evaluation: caller `evaluate_seed` lets it propagate, marks the seed `failed` with the diagnostic in `status.json`, and exits with code 6; no partial metrics are written for the condition.
- FGSM: `grad = torch.autograd.grad(loss, x_in)[0]` where the loss is cross-entropy with `reduction="sum"` over the batch so the sign is independent of batch size scaling (sign is invariant to positive scale; documented). Update `x_adv = project(x + eps * sign(grad), lower, upper)`. Zero gradient entries give sign 0 and the entry stays at `project(x)` (documented). Note for x outside [0,1] the projection also moves an entry by up to eps from x toward the interval, which is the intersection semantics; the perturbation size is still `<= eps`.
- PGD: random start `u ~ Uniform(-eps, eps)` drawn from a dedicated `torch.Generator(device="cpu")` seeded per batch (below), `x_adv = project(x + u, lower, upper)`; each of `steps` iterations: forward, loss, `autograd.grad` w.r.t. the input only, `x_adv = project(x_adv + alpha * sign(grad), lower, upper)`. The final iterate is returned (no best-iterate selection, no early stop).
- Random-start seed derivation (replaces B's `seed*10000 + batch_idx` and the config's mismatching "training seed" claim): `batch_seed = int.from_bytes(sha256(f"pgd-random-start|{training_seed}|{batch_index}".encode()).digest()[:8], "big") & (2**63-1)`, used with a local `torch.Generator`; the global RNG is never reseeded or consumed by attacks. Batch order is the natural row order of the test partition with the fixed `attack_batch_size` 64 from the config, so replay is deterministic on the same platform.
- The model is put in `eval()` at entry (assert via `not model.training`), parameters get `requires_grad_(False)` temporarily for gradient computation only through input (restored in `finally`), no `.grad` is accumulated on parameters, and `state_hash` before/after is asserted equal by the evaluation caller.
- Clean evaluation (`compute_logits`) calls only `assert_clean_inputs_finite` and the model under `torch.no_grad()`; no clamp, no scaling modification. Out-of-range finite values pass through unchanged.
- Documented limits: perturbations are on normalized sequence tensors (so each of the 50 repeated time steps is perturbed independently, not a single feature vector); they do not preserve protocol validity, flow semantics, integer/categorical feature types or the 50-fold repetition structure; evaluation is final-iterate. These sentences appear in the protocol, config and report.

Arithmetic convention [R13]: all bounds and comparisons are done in float32 (`x`, `eps` converted with `torch.tensor(eps, dtype=torch.float32)`), and `lower > upper` is evaluated on the float32 results. Test inputs are written as `np.float32` literals, and expected bounds are recomputed in float32 inside the test, never as Python-double constants.

Edge cases (float32 values): `x = 1.0`, eps 0.10 gives lower `float32(0.9)`, upper 1.0; `x = 0` gives [0, `float32(0.1)`]; `x = 1.05` gives [`float32(0.95)`, 1.0] (original point outside the set, documented); `x = 1.2` and `x = -0.2` are clearly infeasible (lower 1.1 > upper 1.0; lower 0 > upper -0.1). The boundary case `x = 1.10` is NOT used as a pass/fail example, since in float32 `1.10 - 0.10` may round to slightly above or below 1.0; the tests assert only clear cases plus a boundary test that computes the expected outcome with the same float32 formula. NaN/inf rejected before projection; empty arrays raise `ValueError`.

Focused tests (`tests/test_adversarial_domain.py`, CPU, tiny models; no upstream import needed except one fixture test using a randomly initialized `StandardTransformerIDS` from the pinned upstream on a handful of saved train rows):

1. in-range inputs: outputs within `[0,1]` and within eps of x; sample of 3 hand-built tensors.
2. out-of-range feasible (`x=1.05`, `x=-0.05`, eps 0.10): outputs within `[lower, upper]` exactly (same float32 bounds recomputed) for FGSM, PGD init and every PGD iterate (hook via a returned trajectory in a test-only `return_trajectory=True` argument, default False and not used in production).
3. infeasible (`x=1.2`, `x=-0.2`): `InfeasibleConstraintError`; message includes count and index; input array unchanged; no partial output.
4. eps-zero identity: `array_equal`, not the same object/memory (`np.shares_memory` False), model never called (a model stub raising on call), also with out-of-range x.
5. perturbation and domain bounds: `|x_adv - x| <= eps + 1e-6` (float32 slack documented), `x_adv >= lower` and `<= upper` exactly, and `x_adv in [0,1]` whenever `x` in [0,1].
6. finite nonzero gradients: for the real-architecture fixture, input-gradient is finite everywhere and has at least one nonzero entry per sample on a diagnostic batch; also a 2-layer linear model with a known gradient where the FGSM output equals the hand-computed value.
7. eval mode and unchanged weights: model starts in `train()`, attack run, `model.training` is False inside (checked by a stub recording mode), `state_hash` equal before/after, `param.grad is None` for all parameters.
8. deterministic replay: same `(seed, batches)` gives bit-identical PGD output; a different seed differs; the global torch RNG state is unchanged after the call.
9. clean evaluation accepts finite out-of-range inputs unchanged (logits finite; input array not mutated) and rejects NaN.
10. config consistency: the config's attack parameters equal the function defaults and the runner's call arguments (parsed from the config, no literals in the runner).
